# Anti-Patterns Encyclopedia

## Overengineering
Building for hypothetical future needs instead of current requirements.

## Shallow Abstraction
An abstraction that adds indirection but removes no complexity.

## God Class
One module owns too many unrelated responsibilities.

## Temporal Coupling
Correct behavior depends on call order or timing.

## Leaky Abstraction
Implementation details escape the module boundary.

## Spaghetti Architecture
Dependencies are tangled and change ripples across the system.

## Duplicated Logic
The same rule exists in multiple places and will drift.

## Hidden Side Effects
A function changes state outside its visible contract.

## Massive File
A file is too large to understand, review, or safely modify.

## Rule
Every anti-pattern must be translated into a concrete engineering issue.
