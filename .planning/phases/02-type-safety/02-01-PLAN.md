<objective>
Fix the broken Jest infrastructure so all subsequent test plans can execute. Two blockers exist: (1) `jest.config.js` uses `setupFilesAfterFramework` which is not a valid Jest key — Jest silently ignores it, so `jest.setup.ts` never runs and `@testing-library/jest-dom` matchers are unavailable. (2) Jest and all peer dependencies (`jest`, `jest-environment-jsdom`, `@testing-library/react`, `@testing-library/jest-dom`, `@testing-library/user-event`, `identity-obj-proxy`, `babel-jest`) are absent from `package.json`. This plan fixes both blockers.

Purpose: Unblocks all TYPE-04 through TYPE-08 test plans. Without this fix, `npm test` throws a module-not-found error before any test file can load.

Output: Working `npm test` command that runs the 25 existing tests and loads jest-dom matchers.
</objective>

<task type="auto" tdd="false">
  <name>Task 2: Fix setupFilesAfterEnv typo in jest.config.js</name>
  <files>jest.config.js</files>
  <action>
Open `jest.config.js`. The current line 4 reads:

```javascript
setupFilesAfterFramework: ['<rootDir>/jest.setup.ts'],
```

`setupFilesAfterFramework` is not a valid Jest configuration key. Jest silently ignores unknown keys, so `jest.setup.ts` (which imports `@testing-library/jest-dom`) never runs. Replace this key with the correct one:

```javascript
setupFilesAfterEnv: ['<rootDir>/jest.setup.ts'],
```

This is the only change needed in jest.config.js. Do not modify any other line.
  </action>
